# Handoff — 2026-09-23

## The one thing that matters

**Use `/workspace/venv` on the GPU box. Never rebuild it.**

It is the environment that ran the successful training, it survived the volume copy, and
it looked dead only because a venv hard-codes its interpreter path. One symlink revived it:

```bash
ln -sfn /usr/bin/python3.12 /workspace/venv/bin/python3
```

I rebuilt an environment from `pyproject.toml`'s open ranges before checking this. The
result was **21x slower and forked DataLoader workers stalled outright**:

| | `/workspace/venv` (proven) | fresh build (`/workspace/venv-rebuild`) |
|---|---|---|
| torch | 2.6.0+cu124 | 2.14.0+cu130 |
| opencv-python-headless | 5.0.0.93 | 4.14.0.94 |
| augraphy | not installed | 8.2.6 (pulls numba + non-headless opencv) |
| fork, 4 workers | first batch 0.8s, **36.1 img/s** | first batch 18.2s, then stalls |
| GPU | **~79%** | 0-1% |

Hours went into diagnosing that stall as a loader deadlock. It was not. A `worker_init_fn`
thread cap was written, committed (`6912cb7`) and retracted (`7d885c1`) after a controlled
probe showed it changes nothing. The machine was never at fault: 62G `/dev/shm`,
11.8 GB/s disk, 1M file descriptors.

## The detector retrain was already done

It was top of the previous next-steps list and had in fact completed on the old volume
(`/workspace/retrain-20260918/results/PIPELINE_COMPLETE`). On the 26-page `lieder_boxes` set:

| model | Tempo recall | predicted | fg fraction | Lyrics recall | spurious |
|---|---|---|---|---|---|
| e4 (released) | 0.0% | 16,857 | 0.499 | **49.2%** (384/781) | 7,206 |
| sampler-0.7 | 59.1% | 215 | 0.005 | 0.9% | 114 |
| sampler-0.14 | **59.1%** | **198** | 0.004 | 0.13% | **3** |

The `POSITIVE_RATIO` diagnosis is confirmed — 0.14 fixes Tempo and stops the flood — **but
it destroys Lyrics**, so it cannot replace e4 wholesale. That is the two-detector fusion
case, not a swap.

**Unresolved measurement conflict.** Earlier in the session the same e4 checkpoint measured
**85% Tempo recall on 8 pages with 630 predictions** (`MIN_BOX_AREA=200`); here it measures
**0% on 26 pages with 16,857 predictions**. Same weights, incompatible numbers. Different
page sets and box-area filtering are the likely cause. **Do not gate a release on either
until this is reconciled** — one of them is measuring something other than what it claims.
