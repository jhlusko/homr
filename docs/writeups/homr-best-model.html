Technical note · Optical Music Recognition · 2026-08-30

Arm A: a scan-adapted homr checkpoint

A comparison of the current general-purpose candidate with the pinned upstream homr checkpoint (426), and the controlled experiment that produced it.

Working report · free-running held-out scoring · paired bootstrap intervals over staves

Abstract

Arm A is the current general-purpose candidate checkpoint. It retains real scanned OpenScore String Quartet (OSSQ) crops and the v4 Lieder mixture, but replaces the replay component with PDMX-only replay. The run used seed 42 and six epochs from the common starting checkpoint.

Against pinned upstream checkpoint 426, Arm A improves held-out overall token accuracy by +3.56pp on OSSQ (792 staves), +4.11pp on PDMX (3,349), and +7.30pp on the Lieder-v4 holdout (300). All paired intervals exclude zero. This is an end-to-end comparison, not an attribution of each gain to training data, vocabulary, or code changes.

1  Baseline and scope

What is being compared

The upstream reference is pytorch_model_426-b6fd208…, the pinned release checkpoint. Arm A uses the same staff-level encoder–decoder; it is a continuation of the scan-adaptation line, not a new architecture. All runs use free-running generation. Predictions and references are padded to the longer sequence with a non-matching sentinel, so inserted and omitted material count as errors.

Vocabulary caveat

426 predates time-signature numerator and natural-sign additions. Comparisons suppress timeSignatureBeats_ tokens on both sides, but 426 also has no N lift class. An early missing class shifts later positional tokens. The figures answer how the current pipeline differs from upstream; they do not isolate training quality from vocabulary evolution.

A diagnostic comparison for the training-mixture choice

Arm A was selected not merely because it exceeds 426, but because it improves PDMX over scans_v4 while retaining its scan result: OSSQ −0.09pp (not significant), PDMX +1.10pp (significant), Lieder +0.13pp (not significant). The comparison below is the attribution experiment; it does not suffer from the same broad “upstream versus current vocabulary” interpretation.

4  How Arm A was created

A controlled attribution arm

scans_v4 had the strongest OSSQ result but a small PDMX cost. The follow-up separated two ingredients: real scanned OSSQ crops and replay composition. Arm A retained the OSSQ and v4 Lieder mixture and used PDMX-only replay. Arm B removed scanned OSSQ entirely. Both arms used seed 42 and six epochs from the same start.

5  Scope

What this report does not claim

This does not turn one Arm A seed into a corpus-wide estimate. It also does not promote the rare-numerator continuation as the default: that two-seed targeted experiment repairs 5/ and 12/ metre recognition, but seed 7 has a small significant Lieder cost. Structured heads were trained separately over a frozen rare-numerator core, so their beam, tie, and advance results are not claimed as ordinary Arm A outputs here.

The full experiment record, score files, confidence intervals, and caveats are in BENCHMARKS.md and RUNLOG.md.
