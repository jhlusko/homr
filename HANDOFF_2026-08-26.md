## Two real mistakes made and corrected this session — know about these before repeating them

1. **Overwrote the live ONNX weights cache.** `config.filepaths.encoder_path`/
   `decoder_path` are keyed to the architecture's pinned name, not to whichever
   checkpoint is loaded, and that same path is what `download_weights` populates as its
   local cache. Running `convert_encoder`/`convert_decoder` with `overwrite=True` against
   the default path replaced the real upstream files with our own export. Fixed with an
   `out_dir` parameter on all three `convert_*` functions (default preserves old
   behaviour exactly) — **always pass `out_dir` pointed at scratch** when exporting
   anything that isn't meant to replace the pinned deployment artifact.

2. **My own generate()-wiring test passed on CPU by accident.** `decoder.device` in
   `training/architecture/transformer/decoder.py` auto-detects CUDA when available,
   independent of where the caller's tensors live. The test built its tensors as plain
   CPU tensors, which happened to agree with the CPU-only local venv and failed 8/8 the
   moment it ran on this GPU instance. Fixed by moving both explicitly to
   `decoder.device`. **Lesson**: any test touching a model with device-dependent defaults
   needs to run on the actual target hardware at least once, not just CPU.
